# Xiangqi Studio V0.4 — 复盘打谱与变化研究技术实施与验收报告

## 一、当前问题与根因定位

### 1. 现场问题现象
在 V0.3.5 及之前版本中，普通对弈与残局研究均已稳定，但进入【复盘打谱】页面时：
* 棋盘上的棋子无法点击选中，合法落点不显示，棋子无法拖拽或移动；
* 右侧提示：“当前尚无对局历史，请在对战模式走子后再进行复盘”，无对局时页面完全被阻断；
* 用户无法直接在复盘打谱页面开局排子推演。

### 2. 核心 CSS / JS 根因排查
经深入审查 `src/views/ReplayView.vue`、`src/components/chess/ChessBoard.vue` 与 `src/stores/gameStore.ts` 源码，确认根因如下：
1. **交互事件与属性彻底缺失**：
   * 原 `ReplayView.vue` 中渲染 `<ChessBoard />` 时，未绑定 `@select` 与 `@move` 事件监听器；
   * `:selected-pos="null"` 与 `:legal-targets="[]"` 恒定传入空值；
   * 导致棋盘组件内部的 `onIntersectionClick` 无法触发任何点选或走子动作。
2. **状态严重耦合与污染**：
   * 原复盘步进直接调用了 `gameStore.jumpToStep(step)`，使得在复盘中查看第 2 步时，普通对战主状态机被反向同步为第 2 步，严重违反模块隔离原则。
3. **缺少变化分支数据结构**：
   * 原代码仅简单从线性数组 `gameStore.history` 按步数重建局面，不支持在历史节点派生新走法；
   * 一旦用户在历史第 1 步走出新着法，原结构会直接覆盖后续主线，导致历史丢失。
4. **空状态逻辑死锁**：
   * 当 `history.length === 0` 时硬编码阻断提示，没有提供从标准初始盘面直接打谱的入口。

## 二、架构设计与隔离机制 (State Isolation)

为了杜绝复盘对普通人机对战和 AI 思考状态的任何干扰，V0.4 实现了独立的复盘打谱状态存储：`src/stores/replayStore.ts`。

```
+-------------------------------------------------------------------+
|               gameStore.ts (普通对局 / 残局研究)                  |
|  - board: 对局独立 XiangqiBoard 实例                              |
|  - currentStep, history[] (真实对局记录)                          |
|  - isAiThinking, activeAiSearchId, Pikafish 搜索生命周期          |
+-------------------------------------------------------------------+
                                ^
                                | (单向快照读取，绝不反向污染)
+-------------------------------------------------------------------+
|               replayStore.ts (独立复盘打谱 Store)                 |
|  - board: 专属复盘 XiangqiBoard 实例 (独立的走棋、吃子、将军判定) |
|  - mode: 'replay' (只读回放) | 'manual' (手动打谱与推演)           |
|  - treeNodes: 树状棋谱数据模型 (主线 + 无限级变化分支)            |
|  - currentNodeId: 当前复盘节点指针 (不修改 gameStore.currentStep)  |
|  - selectedPos, legalTargets (专属落点高亮)                       |
+-------------------------------------------------------------------+
                                |
                                v
+-------------------------------------------------------------------+
|               ReplayView.vue (复盘打谱视图)                       |
|  - <ChessBoard @select="selectSquare" @move="makeMove" ... />    |
|  - 双模式切换、分支切换胶囊、一键返回主线、新建打谱工具条        |
+-------------------------------------------------------------------+
```

### 关键隔离保障：
1. **棋盘实例隔离**：`replayStore` 独立实例化 `new XiangqiBoard()`，所有规则校验、走子模拟、FEN 刷新均在独立实例上完成，`gameStore.board` 丝毫不受影响；
2. **引擎调用隔离**：打谱落子绝不调用 `triggerAnalysis(true)`，绝不唤起 AI 落子，不会让黑方 Pikafish 自动走棋；
3. **步数索引隔离**：所有导航跳转只操作 `replayStore.currentNodeId`，不触碰 `gameStore.currentStep`；
4. **对战保护验证**：即使在复盘打谱中进行数十步走子并创建复杂分支，切回普通对战时，对战棋盘、历史和当前回合依然保持原状。

## 三、树状棋谱（Variation Tree）数据结构

为支持从历史任意节点走出新招、生成分支且不破坏主线，采用了标准的树状走法模型：

```typescript
export interface ReplayNode {
  id: string;               // 唯一节点 ID (如 'root', 'node_171000_a1')
  parentId: string | null;  // 父节点 ID (根节点为 null)
  move: Move | null;        // 形成该局面的着法 (根节点为 null)
  fen: string;              // 走完本步后的局面 FEN
  stepIndex: number;        // 步数深度 (root 为 0, 第 1 步为 1...)
  childrenIds: string[];    // 子节点列表: childrenIds[0] 恒定为主线, childrenIds[1..n] 为变化分支
  comment?: string;         // 局面评注
}
```

### 核心树操作：
* **打谱落子（`makeMove`）**：
  * 严格经由 `replayBoard.makeMove(from, to)` 进行中国象棋规则校验；
  * 若当前节点已有相同的子走法，直接平滑步入；
  * 若当前节点走出全新走法，追加为新的子节点；若此前已有其他子节点，系统自动派生为**新变化分支（Variation）**；
  * 原主线（`childrenIds[0]`）及其所有子树完全保留，绝不破坏覆盖。
* **分支切换（`switchVariation`）**：
  * 当父节点存在多种走法应对时，界面自动呈现候选分支胶囊（如 `主: 炮二平五`、`变1: 马二进三`），一键无缝切换。
* **一键返回主线（`returnToMainline`）**：
  * 无论变化深入多少层，点击【回主线】按钮即可一键返回主线在同一步数的节点。
* **撤销一步（`undoCurrentMove`）**：
  * 打谱模式下可随时撤销最后落子，若当前节点无子分支则彻底从树中安全移除。

## 四、界面与交互功能

1. **双模式清晰切换**：
   * **【🔍 棋谱回放】模式**：棋盘只读锁定，支持上一步/下一步/跳转，杜绝误触改动棋谱；
   * **【✏️ 手动打谱】模式**：棋盘完全可交互，点选棋子显示金色脉动实心点或红色吃子准星圈，红黑自动交替，伴随真实木质击子、吃子、将军与胜负音效。
2. **空棋谱直接打谱**：
   * 打开复盘若无对局，默认处于标准初始局面并自动就绪打谱，点击棋子即可直接排局推演；
   * 彻底消除原“当前尚无对局历史，请在对战模式走子后再进行复盘”的阻断。
3. **快捷工具条**：
   * 【撤销一步】：撤回当前打谱着法；
   * 【新建打谱】：一键复位至标准初始盘面从头排局；
   * 【同步对战】：一键将对战模式中的最新对局载入复盘；
   * 【翻转棋盘】：一键对调红黑视角。
